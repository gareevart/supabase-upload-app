# Cloud Playground public beta

Route: `/projects/playground` (legacy `/playground` redirects), linked from Projects. Anyone can see and edit; every signed-in gareev.de account can run when enabled. The database rollout switch is off on a fresh migration. The site functions only orchestrate; they do not evaluate user code.

## Setup

1. Apply `migrations/create_playground_quota.sql` and then `migrations/remove_playground_daily_start_limit.sql` in the target Supabase environment. The RPCs and the singleton lease are service-role-only. Check that anonymous and authenticated callers cannot invoke the RPCs.
2. Make sure Sandbox and Vercel OIDC are available for the target project. For local smoke tests, link the correct Vercel project and use `vercel env pull` (OIDC tokens expire). Keep all deployment credentials server-side; never pass them to a VM.
3. In the target database, turn on the matching `playground_quota.preview_enabled` or `playground_quota.production_enabled` switch when ready. The preview switch applies only to Preview; production remains off until verified. Existing Supabase URL, anon key, and service-role key must point to the same environment. No extra Sandbox token is needed on Vercel with OIDC.
4. Redeploy if environment configuration changed. Verify signed-out visitors can read the budget, signing into an ordinary account enables cloud runs, and signed-out and cross-origin requests cannot consume the quota.

## Smoke test

- In Vercel **Preview**, open **Terminal → Linux terminal → Start Bash**. Test `pwd`, `cd`, a pipe, Ctrl+C, and the official interactive `npm create @gravity-ui`; they use a real PTY in one ephemeral VM, with project files and `node_modules` surviving between commands. The workspace editor is read-only while Linux is active; **Sync files** imports text files into the draft, and **Save and stop** also syncs. Sync before the 10-minute timeout; binary files, symlinks, dependency folders and common build outputs are omitted from the draft. Reconnect restores access to the running VM if the WebSocket drops, but starts a fresh Bash process.
- For Vite, run `npm run dev -- --host 0.0.0.0`. Select the reported port (typically 5173) and **Open port in Preview**. Supported ports are 3000, 4173, 5173, 8000 and 8080, and only one is public at a time. Confirm the forwarded page renders, then stop and confirm it is no longer reachable. Links are public until the VM stops; do not use secrets. Terminal sessions have one shared slot and allow outbound traffic only to the public npm registry. No Vercel credential is sent to the browser; the provider issues a session-scoped PTY ticket. Use **Quick commands** for the previous non-interactive npm actions. This Linux mode is disabled in production.
- In **Workspace**, create `example.js`, `example.ts`, and `example.py` using **New file**. Try `console.log(2 + 2)`, `const value: number = 4; console.log(value)`, and `print(2 + 2)`. Run each selected file and verify that the output says 4, the chosen filename and exit code 0. Files in the same workspace can import siblings via an explicit relative path in JavaScript/TypeScript or normal Python imports.
- Reload the same tab and check the active file and edits are restored. Workspace drafts live only in browser session storage for up to one hour; the VM discards its copy after each run. Workspace supports up to 100 text files and 100 folders, including empty and nested folders, with 1.25 MiB of file contents per run. Only the selected entry must be executable. Node 24 defaults to ESM for JavaScript if no workspace package.json is present and strips/transforms TypeScript syntax without type checking. Python uses the managed Python image. Scripts run offline. Python supports only standard-library and local imports. The Terminal displays script output and accepts the supported npm commands in Workspace mode.
- For npm imports in **Workspace**, create root `package.json` with `"type": "module"` for ESM and e.g. `"dependencies": {"is-number":"7.0.0"}`. Generate `package-lock.json` locally with `npm install --package-lock-only --ignore-scripts`, then paste both files into Workspace. In a selected `src/main.ts`, run `import isNumber from "is-number"; console.log(isNumber("42"))`. Verify the installation logs and script output (`true`, exit code 0) are separate. Try a missing lockfile and a mismatched lockfile; neither may run the script. Only public registry dependencies with an npm lockfile v2 or v3 and SHA-512 integrity are supported. No package hooks, custom registries, git/file dependencies, workspaces, overrides, binary downloads by install hooks, or arbitrary console commands. The install phase has a 15-second limit within the 30-second script VM lifetime; large projects may not fit the MVP limits.
- Open **Terminal**, enter `npm create @gravity-ui`, and press Enter. Choose the folder, language, frontend, React, Stylelint, and backend in Terminal, then click **Create and install**. The official initializer receives those choices and is followed by `npm install --ignore-scripts`. A new `gravity-app` folder opens in Explorer; rename the output with `npm create @gravity-ui -- --out demo`. To install a package into the current folder use `npm install @gravity-ui/uikit`; `cd` changes the folder. The temporary VM exposes no port, has access only to the public npm registry, and receives at most the two npm manifests, not the rest of the draft. The draft keeps source and lockfiles, not `node_modules`. This constrained terminal does not offer a Unix shell, arbitrary interactive prompts, npm scripts, or a dev-server preview. The Gravity UI wizard is implemented in the Terminal UI; the registry is fixed to the public npm registry.
- To preview HTML, create a nested `pages/index.html` with a relative stylesheet and a local JavaScript module, then run the HTML file. The page renders next to the editor (stacked on mobile) with its assets on a separate Vercel Sandbox origin. The preview serves HTML, CSS, JavaScript modules, JSON, SVG and text; non-entry dotfiles are not sent. The preview blocks external subresources and lasts up to ten minutes or until Stop. Files are accessible to anyone with the preview URL, so do not include secrets. Browser scripts run in the preview, not inside the VM's HTTP server.
- Import a **public** Vite repository with a root `package-lock.json` or `pnpm-lock.yaml` and an app-directory `package.json` whose `dev` script forwards Vite options. For a monorepo, input the relative app directory (e.g. `apps/editor`). For a clean first test click **Use Gravity UI example** (the Gravity UI team's public Vite template). Check the first render in the embed and the direct link. Check that Stop prevents the URL from remaining live and that an unattended URL expires. Imported files live only on that active VM's disk. No private repos, secrets, persistent projects, or repo editing. Dependency install lifecycle scripts are disabled; the project’s own dev preparation may run offline. A repo that needs native binaries built by install hooks (for example better-sqlite3) or network access while running may require adaptation. The user’s ui-builder editor can be attempted with apps/editor but is not the template baseline.
- Check that a concurrent second request gets 429 and that a confirmed stop permits a new run. When a run disappears or cannot be confirmed stopped, the lease can temporarily remain active until its safety deadline. There is no daily start-count limit. The shared cap is 18,000 seconds (five hours) of VM wall time across environments using the same DB, with one sandbox at a time. The rolling window is 30 days with a 13-minute margin for boundary-overlapping runs. Reserve 30 seconds for scripts or 600 for previews and Terminal commands before starting. Quick-command VMs expire in 165 seconds; Linux sessions expire in ten minutes and refund unused time on confirmed cleanup. Only after confirmed cleanup, return unused time (conservatively measured from reservation). Unknown or timed-out runs are charged in full. The site budget is not the Vercel account’s live meter. Vercel still enforces its own plan quotas, including bandwidth on Hobby.

## Boundaries

SDK-managed ephemeral microVMs, 1 vCPU and 2 GB RAM. Workspace scripts run without egress and cannot expose a port. Workspace npm installs get access only to the public npm registry; only the two npm manifests are present during install, not project source or config. GitHub import and dependency installation permit only GitHub and the public npm registry. Project code starts after blocking VM egress. Use only dependencies obtainable from the public npm registry without install scripts. Preview URLs are separate public Vercel Sandbox origins that anyone with the URL can access until Stop or expiry (at most ten minutes including setup). Do not accept private source or secrets, allow untrusted anonymous runs, or reuse the main origin for preview content. Set project-level spend alerts/budget controls before planning any broader beta.
